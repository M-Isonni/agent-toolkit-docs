Agent Toolkit Lite

This is Agent Toolkit Lite, the free edition: its Evidence and Enhanced Input tools, the agent_toolkit_lite_view tool and its demo map. The full edition, Agent Toolkit, adds nine more domains with the same safety and answers. This guide covers what Lite ships.

Agent Toolkit gives AI agents verified, undoable tools for Unreal Engine 5.8. It adds toolsets for editor domains that Epic's Unreal MCP toolsets don't cover, and every tool that changes your project:

  • checks that it may touch the target (allowed folders, source control);
  • can preview instead of applying (a dry run);
  • runs as one undo step (creating an asset or writing a file on disk can't be undone, and the answer says so);
  • reads the real result back and reports it, so a step that silently did nothing is reported as failed;
  • answers in one compact format, with evidence such as log warnings and thumbnails.

It works with any MCP client (Claude Code, Cursor, Codex, Epic's AI Assistant) through Epic's own Unreal MCP server. It calls no AI model, needs no API key and sends nothing over the network.

Version 1.0.0. Unreal Engine 5.8, Windows editor; tested on 5.8.4. A 5.9 version is planned after the final 5.9 release. What each version changed is in the Changelog.

Quick start

1. Install and enable

  1. Install Agent Toolkit from Fab and add it to your Unreal Engine 5.8 project.
  2. Open the project. Agent Toolkit enables what it needs: Model Context Protocol, Toolset Registry and Python Editor Script Plugin. Restart the editor if it asks you to.
  3. Optional: Epic's own toolsets are separate plugins, off in a new project, and Agent Toolkit doesn't need them. To give your agent those too, enable EditorToolset (actors, assets, Blueprints, materials, levels and code mode) in Edit → Plugins, or All Toolsets for every Epic toolset, and restart the editor. All Toolsets also turns on Epic's Game Features plugin: a project you package then needs a GameFeatureData entry in Edit → Project Settings → Asset Manager.

2. Start the MCP server

Epic's MCP server doesn't start by default.

  • For one session: open the console (the ~ key) and run ModelContextProtocol.StartServer.
  • Every time: Edit → Editor Preferences → General → Model Context Protocol → Auto Start Server.

The server listens on http://127.0.0.1:8000/mcp. It only accepts connections from your own machine.

While your agent works, the editor is usually in the background, where Unreal slows it down and every call waits about a third of a second. Turn off Edit → Editor Preferences → General → Performance → Use Less CPU when in Background so that calls take a few milliseconds.

3. Connect your agent

Run ModelContextProtocol.GenerateClientConfig ClaudeCode in the console (or Cursor, VSCode, Gemini, Codex, All): it writes that client's configuration file in the project folder, .mcp.json for Claude Code. Or add the server by hand. For Claude Code, put this .mcp.json in the folder you start Claude Code from:

{
  "mcpServers": {
    "unreal": { "type": "http", "url": "http://127.0.0.1:8000/mcp" }
  }
}

Start the Unreal Editor before your agent. A client that started first can reconnect: in Claude Code, run /mcp and reconnect unreal.

4. Tell your agent about Agent Toolkit

Agents reach for what they already know. An agent that can also run Python in the editor or edit your files may make a change by hand and skip the toolkit's checks, evidence and undo. Add this to your agent's instructions (CLAUDE.md for Claude Code, AGENTS.md for Codex, the project rules for Cursor):

This Unreal project has the Agent Toolkit plugin. For changes in the Unreal Editor, use its MCP toolsets (agent_toolkit_lite.*) before Python or editing files: they check the result, can be undone and return evidence. Call a tool through call_tool with the toolset name and the short tool name, for example toolset_name "agent_toolkit_lite.evidence.EvidenceTools" and tool_name "capture_from". When the editor offers Epic's code mode (the toolset editor_toolset.toolsets.programmatic.ProgrammaticToolset), many similar calls whose answers you don't need one by one can go in one execute_tool_script script: a script calls a tool by its full name, such as agent_toolkit_lite.input.InputTools.map, and each call still checks its result and is its own undo step.

5. Check that it works

Ask your agent to list the Unreal toolsets. You should see agent_toolkit_lite.evidence.EvidenceTools and agent_toolkit_lite.input.InputTools (and, in the full edition, the other domains' toolsets), next to Epic's if you enabled them. The agent's MCP tool list should also hold agent_toolkit_lite_view, which shows evidence images from Agent Toolkit responses.

6. Try it in the demo map

Open the demo level, AgentToolkitLitePlayground, and try the prompts of Try it in the demo map: one station for each kind of tool.

Concepts

Responses

Every Agent Toolkit tool answers with the same structure, so your agent learns one format:

{
  "status": "applied",
  "summary": "Mapped IA_Sprint -> LeftShift in /Game/Input/IMC_Default.",
  "changes": [
    { "kind": "modified", "object": "/Game/Input/IMC_Default.IMC_Default", "detail": "mapped IA_Sprint -> LeftShift" }
  ],
  "more": 0,
  "evidence": {
    "postcheck": { "passed": true, "observed": "IA_Sprint mapped to LeftShift" },
    "validation": { "errors": 0, "warnings": 0 },
    "log": { "errors": 0, "warnings": 0, "lines": [] },
    "metrics": { "mappings": "1", "duplicate_keys": "" },
    "images": []
  },
  "undo": { "transaction": "AgentToolkitLite: input.map", "undoable": true },
  "confirmToken": "",
  "jobId": "",
  "error": { "code": "", "message": "", "fix": "" },
  "report": "Saved/AgentToolkitLite/Reports/20261023-101502-a1.json"
}

A typical response is near 300 tokens.

Field Meaning
status applied, previewed, partial or failed (see below)
summary One line saying what happened
changes What changed: kind is created, modified, deleted or moved. At most 20 entries (setting Max List Items In Response); more counts the rest
evidence.postcheck What the tool read back from the real state after the change. applied always means passed: true
evidence.validation Asset validation errors and warnings, when the tool validates
evidence.log Errors and warnings logged during the call, with up to five lines
evidence.metrics Numbers specific to the tool, such as coverage or instance counts
evidence.images Paths of thumbnails and other images. Look at one with the agent_toolkit_lite_view tool
undo The name of the call's undo step, and whether it can be undone
confirmToken Set on the preview of a destructive operation. Send it back to apply
jobId Always empty in Lite: only the full edition's tools start long jobs
error Set when the status is failed: a code, a message and a fix
report The full report on disk, with every change, the request and, in details, any list the summary shortens

A response never grows past Max Response KB (24 KB of JSON by default), so one long answer, such as a describe of a large project, can't fill an agent's context. Over the limit, the answer is cut in this order, each step only while it is still too long:

  1. A summary over 1 KB keeps the lines that fit and ends with "N KB left out: the whole answer is in <files> (read them with any file tool, or Epic's read_file)." The files are <report>.part-1.txt, <report>.part-2.txt and so on, next to the report, each at most 64 KB and cut at line ends, which Epic's read_file tool (EditorToolset plugin) reads. Together they hold the whole summary. More than four files are named as a run: "<first> to <last> (<N> files)". A destructive preview still ends with "Call again with confirmToken to apply.", and on failed the error message, which is the summary, is cut the same way.
  2. The log lines go.
  3. Any other text over 1 KB (the fix, the post-check text, a metric, a change) is cut to 1 KB and ends with "[cut: the report holds it]".
  4. The change list goes (more counts it), then the metrics, then the images.

status, report, undo, confirmToken, jobId and error.code are never cut. The metric answer_left_out_kb gives the size of the summary left out, and the report keeps the whole answer as well. A shorter answer is exactly what it was.

Statuses

Status Meaning
applied Done, and the post-check confirmed it
previewed A dry run: nothing changed. changes lists what would change
partial Some of a batch was done, for example before the time budget ran out. Each finished item is listed
failed Nothing changed, or the change was rolled back. Read error: its message says when a change could not be rolled back (see "Calls inside a batch")

Error codes

Code Meaning What to do
INVALID_ARGS The arguments don't match the tool's schema or allowed values Fix the arguments as the message says
NOT_FOUND An asset, actor, level or layer doesn't exist Check the name or create it first
SCOPE_DENIED The target is outside the allowed content or disk paths Choose another path, or change Allowed Content Paths in the settings
SOURCE_CONTROL A file is locked by someone else, read-only, or the check-out failed Ask the lock owner, or check out the file
PRECONDITION The editor isn't in a state that allows the call (Play In Editor running, level not loaded, confirmation needed) Do what the fix says, then call again
ENGINE_ERROR The engine raised an error, or a rollback failed; the message says which, and what to undo by hand Read the message and the report
POSTCHECK_FAILED The call ran, but the real state isn't what it should be; the change was rolled back Read observed, adjust the request
TIMEOUT The call ran out of time before its work could be verified; any partial work was rolled back Split the request into smaller ones
NOT_SUPPORTED Not possible in this configuration, for example a dry run the operation can't simulate Use another mode or tool

Safety

One undo step per call

Every call that changes the project is one undo step named AgentToolkitLite: <tool>. Edit → Undo (Ctrl+Z) reverts the whole call. The response says whether the call can be undone (undo.undoable).

Creating assets can't be undone. Unreal doesn't undo the creation of an asset cleanly, so tools that create assets (for example a new input action) answer undoable: false. To revert one, delete the asset in the Content Browser. If such a call fails, it deletes the assets it created itself, without touching your undo history, and lists them as deleted in changes.

Agent Toolkit only ever undoes its own step. If you or another tool changed something after the agent's call, "undo the last agent call" stops with PRECONDITION instead of reverting your work. Undo your newer steps first, or leave the agent's change in place.

Calls inside a batch

Some tools hold an undo step open while they run other tools, for example Epic's script toolset when it runs a batch of calls. An Agent Toolkit call inside such a batch becomes part of the batch's undo step: its response says undoable: false and names the batch in undo.transaction. If its post-check fails, the change stays in place and the error message says so ("NOT rolled back"); undo the batch to revert it. simulate isn't available inside a batch (NOT_SUPPORTED).

Every change is verified

Each tool reads the real state back after changing it (the post-check). If the result isn't what it should be, the tool rolls the change back and answers failed with POSTCHECK_FAILED and what it observed. A tool can't report applied without a passing post-check.

Dry runs

Mode What happens
plan The tool computes what it would change and touches nothing. Every Lite tool that changes the project offers it

It answers previewed, with the predicted changes in changes. A plan is checked: if a tool changed anything during a plan, the change is rolled back and the call answers failed, so a preview never changes your project.

A call that doesn't choose a mode follows Default Dry Run in the settings: when it is on, such calls preview, and only calls that ask for none apply. Tools that only read (captures, logs, describe) always run.

Tools whose changes happen outside the undo history, such as creating assets or saving files, can't be checked that way, so they handle plan themselves; a tool that can't answers NOT_SUPPORTED instead of previewing.

Destructive operations need confirmation

Deleting or overwriting assets, or touching more objects than Destructive Object Threshold, takes two calls. The first answers previewed with a confirmToken. The second, with the same request plus that token as its confirm_token argument, applies the change. A token works once, for the same tool, targets and arguments, for ten minutes. Turn this off with Require Confirm For Destructive in the settings.

Dialogs never block the agent

While a tool runs, editor dialogs are answered automatically with their default choice, so a "Save changes?" prompt can't freeze the agent session. When that happens, the dialog's text and a call stack appear in evidence.log.

Time budget

A long batch stops when Default Time Budget Seconds runs out and answers partial, listing what it finished and verified. If nothing was finished, or the work done so far couldn't be verified, it rolls that work back and answers failed with TIMEOUT.

Calls that wait for the editor

evidence.pie_start answers once the game runs, and evidence.pie_stop once the editor is back in edit mode; dialogs never block them.

Source control notes

When a call checks files out, or finds files that aren't under source control, the response says so in evidence.metrics.source_control, for example "Checked out 2 file(s)." Checked-out files stay in your default changelist; Agent Toolkit never submits them. If a provider is selected but not connected (for Git: git isn't found, or the project isn't a repository), calls that would edit existing files answer SOURCE_CONTROL and ask you to reconnect, or to set the provider to None if the project doesn't use one.

Many calls at once: Epic's execute_tool_script

Unreal Engine 5.8's EditorToolset plugin, off until you enable it (see Quick start), has a code mode: the toolset editor_toolset.toolsets.programmatic.ProgrammaticToolset, whose execute_tool_script runs a short Python script that calls other tools and returns only what the agent needs. Agent Toolkit's tools work from it unchanged. A script calls a tool by its full name, the toolset and the tool, for example agent_toolkit_lite.input.InputTools.map, and gets the same response as a direct call, failed answers and their fix included.

  • When to batch: many similar calls whose answers the agent doesn't need one by one, such as capturing a level from ten cameras with evidence.capture_from. A tool that already takes a list, such as evidence.save_assets with its paths, batches by itself: one direct call is enough.
  • What to keep direct: a call whose answer decides what comes next, such as a plan the user should see first or a confirm_token.
  • Undo: the script runner opens no undo step of its own, so every change in a script is its own step, named after its tool. A script of 50 changes leaves 50 undo steps, and Ctrl+Z takes them back one at a time. (Calls inside a batch, above, describes a runner that holds one step for the whole batch.)
  • Dry runs: each call takes its own dry_run; a script of plan calls changes nothing.
  • Records: every call in a script has its own report and its own line in the call log, as a direct call does.
  • Arguments: arguments of the wrong type, such as text for a vector, never reach the toolkit: the script fails with Epic's "could not convert incoming function input params" instead of a response. Epic hands the responses to the script as dictionaries whose get() takes no default, so index them with [].

What Agent Toolkit adds

An AI agent can already change an Unreal project without this plugin. Epic's MCP server serves Epic's general toolsets once their plugins are on, Python remote execution runs any editor Python, and the agent can edit the project's files. This chapter shows what changes when Agent Toolkit is installed: measured on real tasks, with examples. It grows with every domain.

How it was measured

  • The agent: Claude Code 2.1.319 with Claude Opus 5.5, running headless on Unreal Engine 5.8.4 (changelist 58902052). Nobody answers its questions.
  • The plugin: Agent Toolkit 0.1.0 at the release candidate, commit e0ecb48.
  • The same tools in every run: Epic's MCP server with all of Epic's toolsets (the All Toolsets plugin on), Python remote execution and the project's files. In every setup the agent's shell is allowed python commands only, so some other commands were refused, and the agent's file tools are refused Agent Toolkit's own folder; a run that reached it anyway is left out (see below).
  • The same prompts in three setups:
    • without: the editor without Agent Toolkit;
    • with: Agent Toolkit installed, nothing else changed;
    • with + instruction: Agent Toolkit plus the instruction from the quick start (step 4).
  • Checked after every run, on the editor and the files, not on what the agent says:
    • Is the task really done?
    • Does Ctrl+Z take the change back?
    • Did the agent claim a success it didn't have?
    • Did the editor survive?
  • Three tasks for Lite's tools, two runs per task and setup, from a pass of sixteen tasks over the full edition's domains. The runs used the full edition, whose Evidence and Enhanced Input tools are Lite's. Turns, tool calls, tokens, time and cost are medians of the two runs. Tokens count everything the model read and wrote, cached or not. Cost is API-equivalent, that is what the run would cost on the Claude API.
  • Runs that don't measure an ordinary project aren't counted. A run without the plugin that read Agent Toolkit's own files, or a run that called the test project's own helper code, is left out and run again.
  • The machine: AMD Ryzen 9 5950X (16 cores), NVIDIA GeForce RTX 3090, 64 GB RAM, Windows 10. Times depend on the machine. Cost, tokens and results depend mostly on the model and on the tools' answers.
  • Measured on 2026-11-07 (pass 2026-11-07-e0ecb48).

With the instruction, no run crashed the editor or claimed a success it didn't have, and Ctrl+Z took the sprint input back in every run; without the plugin, in none. Its cost was lower on all 3 tasks, and the medians add up to $0.72 API-equivalent against $1.81 without the plugin: 40 %. It used fewer tokens on all 3.

What it adds, with examples

Times and costs below are medians, with the quick start's instruction against without the plugin, unless a sentence says otherwise.

The editor stayed up

No run with Agent Toolkit crashed the editor: 12 runs of Lite's tasks, and 64 over the full edition's sixteen.

Ctrl+Z takes the agent's work back

Every Agent Toolkit edit is one undo step; new assets and files written to disk can't be undone, and each answer says whether its change can be. In the sprint task, Ctrl+Z removed the key mappings and the project-wide context in every run with the plugin, with or without the instruction. With the instruction the task also took 37 s instead of 76 s, and $0.27 instead of $0.47 API-equivalent.

Without the plugin, the agent did the same task just as well with Epic's MCP tools, but Ctrl+Z took nothing back: the check found no undo step after either run.

  • Epic's object tool set the key mappings without recording an undo step.
  • Epic's settings tool writes the setting straight to the config file.

Evidence in fewer steps

  • Capture and map check: with the toolkit, the agent finished in 49 s instead of 114 s, at under half the cost. It took 10 turns instead of 23.
  • Play capture: 21 s instead of 65 s, at under a quarter of the cost.

Without the plugin, the agent spent its turns finding a way to make an image and read the map check:

  • in one evidence run, 5 calls failed and one returned an image too large to read before the agent typed a screenshot command into the editor's console box with Epic's Slate inspector; it left your viewport camera at the top-down view;
  • the other evidence run spawned a capture camera from Python and deleted it afterwards;
  • both evidence runs ran the map check as a console command and read its messages from the editor log;
  • both Play runs had a shell command refused and typed a screenshot command into the editor's console box.

With the plugin:

  • evidence.capture_from renders from any camera without touching your viewport, and checks the image before it reports it;
  • evidence.map_check runs the editor's map check on the current level and returns the errors and warnings as data, for example StaticMeshActor_2 Static mesh actor has NULL StaticMesh property;
  • evidence.pie_start, pie_capture and pie_stop each answer once the editor is in the state they report.

Safer settings

To make the sprint context active for every player, the agent without the plugin used Epic's settings tool. That tool replaces the whole list of default contexts, and the change goes straight to Config/DefaultInput.ini. In a project that already has default contexts, the list it writes is the only one left.

Agent Toolkit's input.add_to_player adds to the list or updates it, and can be undone. Nothing reaches the file until evidence.save_assets writes it after the source-control check.

Mistakes caught before they cost you

Agent Toolkit tools check what they are given and say how to fix it, before anything changes. Some of the checks:

  • A misspelled key such as LeftShfit is refused, with the right name suggested. In Python, a misspelled key makes a mapping that never fires.
  • A mapping context stored in a plugin can't be a default context, because Enhanced Input applies default contexts from game content only. The tool refuses it instead of failing silently.
  • A change while Play is running is refused, so the agent doesn't edit the level the game is using.

What it doesn't change

  • The tasks get done without it. Without the plugin the agent did all three tasks in every run, with Epic's tools and Python. What Agent Toolkit adds there is undo, speed and a lower cost.
  • Your agent has to use it. Without the quick start's instruction, an agent with Python remote execution can make a change in Python instead, which skips the toolkit's checks and undo. Add the instruction from step 4 of the quick start.
  • The sample is small: three tasks, two runs each, one model, Unreal Engine 5.8.4 and one machine.

Measuring keeps the toolkit honest

Measuring also caught a bug in Agent Toolkit itself: its images were darker than the viewport. Unreal's scene capture writes linear colour, and the toolkit saved it without converting it to sRGB.

After the fix, an evidence image of the test level is within 0.04 of the viewport's own screenshot, and an automated test keeps it there. The results above were measured with the fix.

Evidence tools

The evidence toolset lets your agent see what happened and check it: screenshots of the level, the editor log, and (further down) map check, asset validation, saving and Play In Editor. It works after any tool, Epic's included, and it is part of both Agent Toolkit and Agent Toolkit Lite.

Toolset name: agent_toolkit_lite.evidence.EvidenceTools.

Screenshots

Every capture is written to the evidence folder (Evidence Directory, Saved/AgentToolkitLite/Evidence by default) and verified: the call fails with POSTCHECK_FAILED if the file is missing, empty or not the requested size. The response lists the image in evidence.images. To look at it, your agent calls the agent_toolkit_lite_view tool with that path.

Tool What it captures
capture_viewport What the active level viewport shows
capture_from The level from a camera you place (location, rotation), or framing one actor (focus)

Both take width and height in pixels. With 0 (the default), the image is Thumbnail Size wide and 16:9. Sizes go from 32 to 4096 pixels.

Examples of arguments:

{ "focus": "Cube" }
{ "location": { "x": 0, "y": -800, "z": 400 }, "rotation": { "pitch": -20, "yaw": 90, "roll": 0 }, "width": 1024 }

focus takes an actor's label as shown in the Outliner, its name, or its path. The camera then looks at the actor's bounds from above and in front, far enough to see all of it. An unknown actor answers NOT_FOUND.

Captures need rendering: in an editor started with -NullRHI they answer PRECONDITION. Each capture also deletes evidence images older than Evidence Retention Days.

The editor log

Tool What it does
log_mark Marks the log now; the mark is in evidence.metrics.mark
log_since Reports the errors and warnings logged since a mark

log_since takes the mark, max_lines (1 to 50, default 5) and include_info. Without include_info, it counts errors and warnings and lists them, errors first. With include_info, it lists ordinary lines too, in the order they were logged. The counts are in evidence.log.errors and evidence.log.warnings.

A typical use: log_mark, then any other tool (or a Play session), then log_since to see what went wrong.

Map check and asset validation

Tool What it does
map_check Runs the editor's map check on the current level, without opening its window
validate_assets Runs the project's asset validators (Data Validation) on the assets in paths

map_check puts the counts in evidence.metrics.errors and evidence.metrics.warnings, and the first messages in evidence.log.lines, errors first. Messages name actors by their object name (for example StaticMeshActor_2), not by their Outliner label.

validate_assets reports how many assets have errors or warnings in evidence.validation, lists the failing assets in the summary, and gives the first validator messages in evidence.log.lines. An asset that doesn't exist answers NOT_FOUND.

Saving

save_assets is the only Agent Toolkit tool that writes to your project's files. Every other tool leaves its changes unsaved, so you can review them, undo them, or save them yourself.

  • paths: the assets to save. They must be inside Allowed Content Paths, and the Source Control Policy applies (files are checked out first when needed).
  • settings: also writes the project settings that tools changed in memory, such as the input defaults that add_to_player sets, to their config files (for example Config/DefaultInput.ini). The config file goes through the source-control check too.
  • dry_run: plan lists what would be saved and writes nothing.
  • confirm_token: saving more assets than Destructive Object Threshold takes two calls; the first answers previewed with a token, the second applies it (see Concepts).
  • source_control_approved: with the Ask First policy, set it to true once the user agreed to the check-out.

The post-check confirms that every saved asset is clean and its file exists. Saving isn't an undo step (undoable: false): Ctrl+Z reverts a settings change in memory but not the config file already written. While Play In Editor runs, save_assets answers PRECONDITION.

Play In Editor

Tool What it does
pie_start Starts Play In Editor in the current level and answers once the game runs
pie_stop Ends the session and answers once the editor is back in edit mode
pie_capture Captures what the player's camera sees, as a verified PNG

pie_start never waits on a dialog: if Blueprints need compiling, the editor's default choice is taken. It answers PRECONDITION when a session already runs, and pie_stop and pie_capture answer it when none does. While a session runs, tools that change the project answer PRECONDITION, and so do capture_viewport, capture_from, validate_assets and the Enhanced Input describe, because the editor doesn't expose the editor level and its assets to tools during Play. pie_capture, map_check and the log tools keep working.

The game draws its first frame on the editor's next tick. A pie_capture in the same frame as pie_start (possible only when calls are batched) answers PRECONDITION; call it again a moment later.

Every capture's post-check also rejects a blank image (every pixel the same colour), so a black frame is never reported as evidence.

Enhanced Input tools

The Enhanced Input toolset lets your agent set up player input: input actions, mapping contexts, the keys mapped to each action, and which contexts players get by default. It is part of both Agent Toolkit and Agent Toolkit Lite.

Toolset name: agent_toolkit_lite.input.InputTools.

Creating actions and contexts

Tool What it creates
create_action An input action (IA_ asset), with a value_type: bool (default), axis1d, axis2d or axis3d
create_context An input mapping context (IMC_ asset)

Both take the new asset's path (for example /Game/Input/IA_Sprint), an optional description, and dry_run (plan lists what would be created and creates nothing).

  • The path must be inside Allowed Content Paths and use letters, digits and underscores; anything else answers INVALID_ARGS before the editor is involved.
  • An asset that already exists at the path answers PRECONDITION and is left untouched; the editor's "overwrite?" dialog never opens.
  • Creating an asset can't be undone with Ctrl+Z (undoable: false); delete the asset to revert. If the call fails after creating it, the asset is deleted for you.
  • New assets are not saved. Call save_assets to save them.

Example:

{ "path": "/Game/Input/IA_Sprint", "value_type": "bool", "description": "Run faster while held" }

Mapping keys

map maps one or more keys to an input action inside a mapping context, as one undo step:

Argument Meaning
context, action Paths of the mapping context and the input action
keys Key names, for example LeftShift, SpaceBar, Gamepad_LeftTrigger
modifiers Optional, comma-separated, applied to every key: negate, swizzle, dead_zone, smooth
triggers Optional, comma-separated, applied to every key: down, pressed, released, hold, tap
replace Remove the action's earlier mappings in this context first
dry_run plan lists what would change
source_control_approved With the Ask First policy, true once the user agreed to check the context out
  • A misspelled key answers INVALID_ARGS and the fix suggests the closest key names ("LeftShfit" → LeftShift). Modifier and trigger names ignore case and underscores, so Down and DeadZone work too. An unknown modifier or trigger lists the valid names.
  • The post-check reads the context back and finds every requested key on the action, with its modifiers and triggers.
  • Mapping a key the action already has in this context updates that mapping (its modifiers and triggers) instead of adding a second one, so calling map again is safe.
  • A key used by more than one mapping in the context is reported in evidence.metrics.duplicate_keys and in the summary. The call still succeeds: sharing a key between actions can be intended.
  • Paths can be package paths (/Game/Input/IA_Sprint) or the object paths that responses list (/Game/Input/IA_Sprint.IA_Sprint); this holds for describe and add_to_player too.
  • Edit → Undo (Ctrl+Z) reverts the whole call.

Example:

{ "context": "/Game/Input/IMC_Default", "action": "/Game/Input/IA_Sprint",
  "keys": ["LeftShift", "Gamepad_LeftTrigger"], "triggers": "down" }

Making a context active for players

add_to_player adds a mapping context to Project Settings → Enhanced Input → Default Mapping Contexts. Every player gets those contexts when Play starts, with no Blueprint changes. It takes the context (under /Game/, because Enhanced Input reads default contexts from game content only), an optional priority (higher wins when two contexts map the same key) and dry_run.

  • The change takes effect at the next Play and can be undone with Ctrl+Z.
  • It isn't saved to disk until you call save_assets with settings set to true, which writes Config/DefaultInput.ini. Closing the editor without saving loses it; the editor doesn't ask about settings.
  • Adding a context that is already listed with the same priority changes nothing and still answers applied; with another priority, the priority is updated (the change says "priority 0 -> 2").

To check it in the game, start Play with pie_start, then call active_contexts. It lists the mapping contexts the player has right now, highest priority first, and takes an optional player index (0, the first player, by default).

  • Outside Play it answers PRECONDITION, with pie_start in the fix.
  • Right after pie_start, in the same editor frame, players don't have their contexts yet; the answer asks to call again in a moment.
  • A player index with no local player answers NOT_FOUND.

Reading a context

describe takes a context path and lists its mappings as "Action: Key [modifiers] [triggers]". It reports:

Metric Meaning
mappings How many key mappings the context has
actions How many different actions they map
duplicate_keys Keys that more than one mapping uses, comma-separated (empty when none)

A context that doesn't exist answers NOT_FOUND.

Troubleshooting

The agent can't reach Unreal

  • "ECONNREFUSED" or "failed to connect": the editor or its MCP server wasn't running when the agent started. Start the server (ModelContextProtocol.StartServer), then reconnect the client (in Claude Code: /mcp).
  • The server doesn't answer after an editor restart: reconnect the client. MCP clients don't always reconnect on their own.

Every call takes a third of a second or more

When the editor isn't the active window, Unreal slows it down to 3 frames per second. The MCP server answers once per frame, so each request waits up to about 330 ms. An agent that makes many calls feels slow.

Fix: Edit → Editor Preferences → General → Performance → Use Less CPU when in Background: turn it off. Requests then take a few milliseconds. Don't minimize the editor: with every editor window minimized, Unreal slows it down even with this setting off.

When the MCP server starts with the editor and this setting is on, Agent Toolkit writes this tip once to the Output Log at start-up. It never changes the setting for you.

An answer ends with "KB left out"

The answer was longer than Max Response KB (24 KB by default). Its summary keeps the lines that fit, and the whole summary is in the .part-<n>.txt files it names, under Saved/AgentToolkitLite/Reports. Ask the agent to read them, or raise the setting in Project Settings → Plugins → Agent Toolkit if your agent's context has room.

If it says "the parts couldn't be written", the project's Saved folder refused the files (full disk or no write access); the report it names still holds the whole answer. If it says "no report could be written", nothing on disk holds the rest: free space in Saved, then call again.

Both Agent Toolkit and Agent Toolkit Lite are installed

Only one edition can be active. When both are enabled in a project, the Lite edition stays inactive and writes "Agent Toolkit Lite is inactive because Agent Toolkit is enabled" to the Output Log. Remove Agent Toolkit Lite from the project (Edit → Plugins); the full edition includes everything Lite does.

A call answered failed

Read error.code, error.message and error.fix in the response; the fix says what to do. The summary is the same message. The full report, with every change and, for engine errors, the traceback, is at the path in report; when the tool had written a summary before it failed, the report's details keep it.

You see Usually means
SCOPE_DENIED The target is outside Allowed Content Paths or inside a plugin's content
SOURCE_CONTROL Someone else holds the file, or it is read-only and not under source control
PRECONDITION Play In Editor is running, a confirmation is needed, or a newer step blocks an undo
POSTCHECK_FAILED The change didn't produce the expected result and was rolled back

My undo history disappeared

The editor clears the undo history when a level is closed and opened again, and when actors are unloaded. Agent Toolkit never does either on its own.

Agent Toolkit isn't there in a commandlet

Agent Toolkit doesn't load in commandlets (UnrealEditor-Cmd -run=...): a commandlet's Python and Blueprints can't call its tools or libraries. Call the tools from the editor, through your agent, instead.

Dialog text and a call stack appear in evidence.log

An editor dialog opened during a tool call and was answered automatically with its default choice, so it couldn't block the agent. The text tells you which dialog it was.

Where Agent Toolkit writes files

Everything goes under your project's Saved/AgentToolkitLite folder:

Folder Contents
Evidence Thumbnails, deleted after Evidence Retention Days
Reports One JSON report per tool call
Calls One line per tool call, one file per day (setting Call Log Enabled)

Nothing leaves your machine.

FAQ

What does Agent Toolkit need?

Unreal Engine 5.8, Epic's Model Context Protocol plugin (experimental and off by default; the Quick start turns it on) and an MCP client for your agent. It is tested in the Unreal Editor on Windows.

Some tools of the full edition need an optional Epic plugin: SmartObjects plus a behavior plugin such as GameplayBehaviorSmartObjects for the Smart Objects tools, MetaSound for the MetaSound tools, IK Rig for IK Rig and retargeting, and PoseSearch for the Pose Search tools. When such a plugin is off, its tools aren't offered and the rest work as usual.

How does Lite differ from the full edition?

Agent Toolkit Lite is free. It has the core, the agent_toolkit_lite_view tool, and the Evidence and Enhanced Input toolsets. The full edition adds Navigation, Smart Objects, Landscape, Foliage, Audio, Sound Cue, MetaSound, animation, World Partition, cook and packaging, jobs and profiling. Both can be installed in one project; Lite turns its own tools off while the full edition is enabled. Each edition has its own demo map.

Which engine versions does it support?

Unreal Engine 5.8 only: Epic's MCP server and toolset registry, which Agent Toolkit plugs into, first appear in 5.8. It is tested on 5.8.3 and 5.8.4.

Lite's toolsets, Evidence and Enhanced Input, need no optional Epic plugin.

Both editions run in the Unreal Editor on Windows (Win64).

Does it send data anywhere?

No. It calls no AI model, needs no API key and sends nothing over the network. Its own files (reports, the call log and evidence) stay in your project's Saved/AgentToolkitLite folder (see "Where Agent Toolkit writes files" in Troubleshooting); the assets and levels your agent asks for go where it asks.

Your agent is another matter: it sends what it reads, tool answers and your project's names, settings and code among them, to its own AI provider. The Unreal Engine EULA doesn't allow engine code and content to be training input for a generative AI program, or prompt input to a program that trains on its input. So use a provider and a plan that don't train on your inputs; some free plans do. Check your provider's data settings before you connect an agent.

What can't be undone?

Most calls that change the project are one undo step, and each response says whether it can be undone (undo.undoable). These can't:

  • creating assets: delete the asset in the Content Browser to revert it;
  • writing files on disk: saved assets and levels, config files that evidence.save_assets writes, and captures.

The tool reference at the end of this guide gives each tool's undo line, and Concepts explains the safety rules.

Which agents and MCP clients work with it?

Any MCP client that connects to Epic's Unreal MCP server: Claude Code, Cursor, Codex or Epic's AI Assistant, for example. The Quick start shows the connection.

Does it change project settings?

Its own settings are in Project Settings → Plugins → Agent Toolkit Lite. One tool changes project settings when asked: input.add_to_player adds a mapping context to Enhanced Input's Default Mapping Contexts. It changes memory only; the config files change when evidence.save_assets saves settings.

Does it work with source control?

Yes. By default tools check out the files they change; the Source Control Policy can ask you first or allow only files already checked out (see Settings). Agent Toolkit never takes a lock someone else holds, and never commits, submits or pushes. Git through the editor's built-in provider is verified; Perforce and other providers are checked with simulated states only.

Can it create a level?

Not with a tool of its own in this version. Create it in the editor (File → New Level), or run this line of editor Python in the Output Log, with its command box switched from Cmd to Python: unreal.get_editor_subsystem(unreal.LevelEditorSubsystem).new_level("/Game/Maps/MyLevel", False). It makes a saved level at that path and opens it. An agent that can run editor Python, for example through Python remote execution (Edit → Project Settings → Plugins → Python → Enable Remote Execution?), can run it for you. From there the toolkit's tools take over. A level tool is planned after launch.

How much does a task cost?

Agent Toolkit calls no AI model, so its tools cost nothing per call. What your agent costs depends on your client and model. What Agent Toolkit adds measures the same tasks with and without the toolkit: turns, time, tokens and cost.

What is code mode?

In UE 5.8, Epic's EditorToolset plugin, once you enable it (see Quick start), can run a short Python script, execute_tool_script, that calls many tools and returns only what the agent needs. Agent Toolkit's tools work from it unchanged. See "Many calls at once" in Concepts.

How do I report a problem?

Write to support through the contact on the plugin's Fab page, with the call's report, the response, your engine version and Agent Toolkit's version. "Getting help" in Troubleshooting says where to find each.
